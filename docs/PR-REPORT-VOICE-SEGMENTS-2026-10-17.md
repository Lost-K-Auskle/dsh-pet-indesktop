## 一、核心特性

报时口播（以及同入口的手动报时）从「整句一次合成 → 出声」改为「按标点切成顺序片段 →
每段单独合成 → 顺序播放」。用户可感变化：报时点到达后**首段合成完即刻出声**，后续段在
上一段播放期间并行合成，整轮的"等出声"从"整句合成耗时"降为"首段合成耗时"。本机当日
实测（第 5 部分，16 轮）：首段合成中位 **3.76 s**、分布 2.95–38.13 s（成功 15 样本；
另 1 轮撞 46 s 看门狗）；对照 10-15 实网的整句克隆 3.08–105.55 s（8 样本中位 31.29 s）
——口径不同（日期/样本），仅作量级参照。两边的共同点是**重尾**（服务端负载）；分段
不改变尾部分布，改变的是尾部到来时的行为：先出声、且超时只损失一段（见第三部分）。

| # | 能力 | 说明 |
|---|---|---|
| 1 | 按标点切段 | 强标点（`。！？；…!?;\n`）总是切；弱标点（`，、,：:`）累计 ≥12 字才切；碎段（<6 字）向后并入；上限 12 段；断点后的收尾符号（`"）】` 等）并入本段 |
| 2 | 逐段合成 | 恰好一个段合成在飞；上段播放期间预取下一段（无并发铺开） |
| 3 | 顺序播放 | 一段播完接下一段；通道被别的音频占用时**就地等待不顶播**（点火时刻例外，见第三部分） |
| 4 | 失败跳过 | 单段合成失败 / 超 46 s 看门狗 → 只跳过该段，其余照播；全部失败才出提示气泡 |
| 5 | 分段预合成 | 报时预合成窗口按段推进（含未点火作业），到点点火可"认领"已就绪的首段直接出声 |
| 6 | 免打扰边沿 | 合成期间进入免打扰：在播段立即停、余段整组丢弃（不浪费后续调用） |

**红线 / 不变量**：
- **单段路径逐字节不变**：文本短于阈值（或切不出多段）时 `split_speech_segments` 原样
  返回全文，走的就是改动前的整句路径——缓存键、播放、气泡全部同构，旧缓存 100% 复用。
- **每段缓存键 = 既有 `cache_key(段文本, cfg)`**：不新增键形态；分段只改「怎么合成、
  怎么播」。
- 既有语义全部保留：通道不顶播（除点火/缓存命中口径）、`_SYNTH_TIMEOUT_S=45` 数值、
  代次丢弃、免打扰、预合成 attach/认领、失败提示口径。

### 实现（两文件）

- **`pet/voice_chime.py`** — `split_speech_segments(text) -> tuple[str, ...]`：纯字符串运算、
  零 IO 零 Qt。规则常量：`SEGMENT_SPLIT_MIN_TEXT=16`（全文短于此不切）、
  `SEGMENT_MIN_CHARS=6`（碎段向后并入）、`SEGMENT_WEAK_MIN=12`（弱标点门槛）、
  `MAX_SPEECH_SEGMENTS=12`（防御上限，超出时反复合并最短相邻对）；ASCII `.` 刻意不在
  强标点内（小数/版本号/英文缩写误伤）。
- **`pet/voice_chime_service.py`** — 主战场（+436/−28）：
  - `_SpeechJob`：分段作业记账（segments/ready/failed/play_next/playing/inflight_index/
    inflight_generation/attached/bubble_*/…），`finished()` = 每段都有结局（播完或失败）且无在飞；
  - `_fire` 接线：attempts 门 → 免打扰闸 → 整句缓存命中（语义不变）→ **切分** → 认领
    （未点火作业 ∧ 全文相同，**在 busy 门之前**——认领不排合成队）→ busy 排队（整句）→
    n>1 走 `_fire_segmented`、n==1 走原整句路径；
  - `_fire_segmented`：认领（挂 attached/气泡、清 failed、`pump(allow_engaged=True)`）
    或新建（先作废场上旧作业）后点火；
  - `_pump_job(allow_engaged)` 三段式：**静音闸**（attached ∧ 免打扰，在预取之前——不
    再起后续段合成）→ **预取**（`_start_job_segment`：恰好一个段在飞；已缓存段零网络
    直接记就绪）→ **顺序起播**（`allow_engaged=False` 时 `_player_engaged()` 真则就地等待，
    点火/认领传 True = 与整句缓存命中"报时例外"同口径，可顶播）→ **收尾** `finished()→_finish_job`；
  - `stop/say_now/stop_current_segment` 等出口整组语义（`_kill_job` 不碰播放器；段在飞时
    代次 +1 丢弃迟到回调）；
  - `_on_synthesized`／`_on_media_status`（END 推进下一段）／`_on_quiet_state_changed`
    （在播段停 + 整组丢）／`_release_stale_busy`（**逐段**看门狗：超时段记 failed +
    跳过日志，其余段照常）逐段口径化；
  - 日志 4 条：`分段播报（n 段）`／`分段合成第 k/n 段`／`分段播报结束（n 段，出声：有/无）`／
    `分段播报第 k 段合成超时/失败，跳过该段`（实机时间线即由这些行重建，见第五部分）。

## 三、实现要点

**为什么切段有效**（本层的全部动机）：整句路径下"听到开头"= 整句合成耗时；分段后
"听到开头"= 首段合成耗时，且第 k+1 段的合成与第 k 段的播放并行。当日实机里首段
（时刻文本，每轮新内容必合成）中位 3.76 s，而 10-15 实网整句克隆中位 31.29 s——
即使把两次测量当作同分布（存在日期偏差），"先出声"的期望等待也少了一整段合成的排队。
**诚实边界**：两边分布都重尾（本日首段 15 样本里 4 个 ≥9.7 s、1 个撞看门狗），分段
缩短的是期望等待与尾部损失半径，**不保证每一轮都更快**（见第四部分）。

**取舍与备选**：
- **不做流式 / 边收边播**：MiMo 无流式接口，响应形态是完整 WAV；分段合成是"服务端
  黑箱"下唯一能提前出声的结构。
- **逐段串行**（恰一个在飞）：不并发铺开——遵守 API 并发纪律，且顺序播放天然只依赖
  下一段；预取深度 1 已覆盖"播放时长 ≥ 下一段合成耗时"的常见情形。
- **`allow_engaged` 双口径**：点火/认领传 True（报时点到了、首段已备好 → 与整句**缓存
  命中**同口径可顶播）；其余所有 pump 调用点传 False（合成完成/END/治愈）——此刻顶播
  会切掉刚被用户触发的音频（点击自言等），就地等待，下一个"通道空出"的拍子再推进。
- **段数上限 12 / 碎段并入**：纯防御，防止超长输入产生调用风暴或"呀！"级碎段。
- **看门狗逐段化而非调大**：45 s 是既有契约（10-15 报告 §四.9 已论证慢在服务端生成、
  与文本长度无关），调大只会拖长队列自适应；逐段化的收益是**失败半径**：一段超时 ≠
  整句静默（实机验证见第五部分 15:01/15:03/15:10 三轮）。

| 看门狗余量最小样本 | 15:15 轮首段 38.13 s（离 46 s 判罚线余 **7.87 s** 安全抵达并出声）；15:14 轮 25.77 s | 同上 |
| `split_speech_segments` 成本 | 报时样句 3.4 µs / 顶满 12 段 72.1 µs / 短文 0.2 µs（n=100,000，`time.perf_counter`） | 新增（可忽略） |
| 帧交付（同机同刻，应用内） | tick p50=16.0 ms / p99=31.0 ms（n=4096，日志自带） | 既有路径，未见扰动 |
| 段级缓存落盘 | 读取时刻（≈15:20）：39 个段级 WAV / 单段 82–315 KB | 新增（与音频总量同阶） |

**结论**：
① **稳态（单段路径）零变化**：同一函数入口，`split` 在 n≤1 时原样返回全文，缓存键、
播放、气泡全部走改动前的路径；旧缓存 100% 复用。
② **新增路径绝对成本**：每段一次合成调用（与整句路径的"一次调用"相比，段数即调用
次数）+ µs 级切分（表格）；首段合成 2.95–38.13 s（n=15，中位 3.76 s），大头在服务端
负载（与 10-15 报告的"慢在服务端生成"结论一致）。
③ **无新系统调用 / 网络形态 / 线程**：复用既有合成 worker 与播放器；每段是多一次
既有形态的 HTTP 合成。
④ **内存与缓存**：段级缓存的字节总量 ≈ 同样音频的整句缓存（同一段音频按标点切片）；
正外部性：quote 来自固定池，重复轮次会命中段级缓存、**零网络**（窗口 16 轮未重复到，
未实测到重复命中样本——如实标注）。

  结构变化，孤儿文件随既有缓存清理策略走。

  10-15 的新接口面以外的任何东西；`split_speech_segments` 只调标准库字符串）。
